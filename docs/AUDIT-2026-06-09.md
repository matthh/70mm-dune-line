## HIGH

### H1 — `window.open` with user-controlled URL (low exploitability, included for awareness)
**File:** `app/Timeline.tsx:357`

```tsx
onClick={() => window.open(m.wikiUrl, '_blank', 'noopener,noreferrer')}
```

`m.wikiUrl` is constructed in `lib/data.ts` as a template string:

```ts
wikiUrl: `https://70mmwiki.com/movies/${m.id}`,
```

`m.id` comes directly from the upstream JSON. If a malicious wiki response injected `javascript:` as an id, this would be an XSS vector. In practice `m.id` is typed as `number` (TypeScript), so a non-numeric id would fail TS compilation — but the JSON is consumed at runtime via a cast (`raw as RawData`), not runtime-validated.

**Fix:** Guard `m.wikiUrl` to ensure it starts with `https://` before passing to `window.open`. Alternatively, validate `m.id` is a positive integer when consuming the JSON.

```ts
// In lib/data.ts, in the DisplayMovie construction:
wikiUrl: `https://70mmwiki.com/movies/${Math.abs(Math.floor(m.id))}`,
```

Or, in Timeline.tsx:

```tsx
onClick={() => {
  if (m.wikiUrl.startsWith('https://70mmwiki.com/')) {
    window.open(m.wikiUrl, '_blank', 'noopener,noreferrer');
  }
}}
```

### H2 — No runtime validation of `movies.json` shape
**File:** `lib/data.ts:264`

```ts
const data = raw as RawData;
```

The entire data pipeline trusts the committed JSON matches `RawData`. The JSON is fetched from a third-party API (`70mmwiki.com`) and committed by a GitHub Actions bot. If the upstream API changes its shape (e.g., renames a field, changes a type), the site silently misbehaves rather than failing loudly.

**Fix (medium-effort):** Add a lightweight runtime assertion or use a schema validator (e.g., Zod, which has no runtime overhead when types match). At minimum, assert `Array.isArray(data.movies)` before iterating.

## MEDIUM

### M1 — `useEffect` with `eslint-disable` for exhaustive-deps
**File:** `app/Timeline.tsx:166`

```tsx
}, [bands, sortMode, active]); // eslint-disable-line react-hooks/exhaustive-deps
```

The `useMemo` depends on `isVisible` (defined inline in the component), but `isVisible` is not listed in the dependency array. The author's reasoning is that `isVisible` is effectively stable relative to `active`, but if `isVisible` is refactored (e.g., pulled out to a `useCallback` or given additional inputs), the missing dep becomes a stale-closure bug.

**Fix:** Either wrap `isVisible` in a `useCallback` so it can be safely listed as a dependency, or inline the visibility check directly in the `useMemo` body without relying on the helper.

### M2 — `useEffect` keyboard handler captures stale `page`/`totalPages`
**File:** `app/AllTimeStats.tsx:253–261`

```tsx
useEffect(() => {
  const onKey = (e: KeyboardEvent) => {
    if (e.key === 'Escape') onClose();
    else if (e.key === 'ArrowRight' && page < totalPages - 1) setPage(page + 1);
    else if (e.key === 'ArrowLeft' && page > 0) setPage(page - 1);
  };
  document.addEventListener('keydown', onKey);
  ...
}, [onClose, page, totalPages]);
```

`page` and `totalPages` are in the dependency array so this is correct — the handler re-registers on every page change. However, `onClose` is an inline function in the parent (`() => setPopup(null)`), which means this effect re-runs on every render of the parent (new function reference each render). This is a minor performance issue — the keydown handler is repeatedly removed and re-added — but not a bug.

**Fix:** Memoize `onClose` with `useCallback` in `AllTimeStatsSection`, or use the functional form `setPage(p => p + 1)` and list only `onClose` and `totalPages` as deps.

### M3 — `at-row.clickable` focus/hover styles use `display: contents` grid row
**File:** `app/globals.css:653`

```css
.at-row.clickable { cursor: pointer; transition: background 0.15s; border-radius: 4px; padding: 4px; margin: -4px; }
.at-row.clickable:hover { background: rgba(200,154,74,0.08); }
```

`.at-row` uses `display: contents`, which means the element itself has no box — `background`, `padding`, `margin`, and `border-radius` on it are ignored by browsers. The hover highlight never renders, and `cursor: pointer` has no effect. The clickable affordance is purely inherited from child elements.

**Fix:** Wrap each category row in a wrapping `<div>` (not `display: contents`) so the background/cursor styles actually apply, or switch from CSS Grid `display: contents` to an explicit row element.

### M4 — `Chip` component defined but never used (dead code)
**File:** `app/Timeline.tsx:388–395`

```tsx
function Chip({ cat, label, color, count, active, onClick }: { ... }) {
```

The `Chip` component is defined (with full typed props including `cat`, `color`, `count`) but is never called anywhere in the file. It was presumably the per-category filter chip before the filter pills were hidden (commit `65bc7d5`). It is dead code.

**Fix:** Remove the `Chip` function. Also remove the now-unused `DEFAULT_ACTIVE` constant if filter chips are truly gone (though `DEFAULT_ACTIVE` is still used to initialize `active` state, so that one stays).

### M5 — `HOST_LB_HANDLES` constant placement
**File:** `app/Timeline.tsx:5`

```ts
const HOST_LB_HANDLES = { slim: 'slim', danny: 'danny', proto: 'protolexus' } as const;
```

This constant is declared before the `import` on line 6, which is unconventional (imports should precede non-import declarations) and could confuse linters. The host handle mapping is also not co-located with the `HOSTS` array in `lib/data.ts`, creating two separate places to update if a host handle ever changes.

**Fix:** Move the import to line 1, then the constant. Consider moving `HOST_LB_HANDLES` into `lib/data.ts` alongside `HOSTS`.

### M6 — `backfill.csv` committed artifact with no ignore rule
**File:** `backfill.csv` (repo root)

`backfill.csv` is a generated artifact produced by `node scripts/backfill-csv.mjs`. It's committed to the repo root but is not needed for the build, tests, or deploy. Over time it becomes stale and misleading.

**Fix:** Add `backfill.csv` to `.gitignore` and remove the committed copy, or move it to a `scratch/` directory already in `.gitignore`.

### M7 — GitHub Actions workflow uses broad `contents: write` on every run
**File:** `.github/workflows/refresh.yml:17–18`

```yaml
permissions:
  contents: write
```

The workflow has `contents: write` scoped to the entire job. If the `node scripts/scrape.mjs` step were ever compromised (e.g., via a supply-chain attack on a dependency), the token could be used to push arbitrary commits.

**Fix:** Split the workflow into two jobs: a `scrape` job with no elevated permissions, and a `commit` job that only runs if there are changes and has `contents: write`. This limits the blast radius.

## LOW

### L1 — No `role` or `tabIndex` on `.bar-col` click targets
**File:** `app/Timeline.tsx:350–380`

Each bar column is a `<div>` with an `onClick` handler that opens the wiki page. It has no `role="button"`, no `tabIndex`, and no `onKeyDown` handler. Keyboard users cannot navigate to or activate individual bars.

**Fix:** Add `role="button"`, `tabIndex={0}`, and an `onKeyDown` handler (Enter/Space triggers `window.open`) to each `bar-col` div.

### L2 — Tooltip position math uses `typeof window !== 'undefined'` fallback
**File:** `app/Timeline.tsx:411–412`

```tsx
const vw = typeof window !== 'undefined' ? window.innerWidth : 9999;
const vh = typeof window !== 'undefined' ? window.innerHeight : 9999;
```

The `Tooltip` component is only rendered from a client component (`'use client'`), so `window` is always defined at this point. The SSR guard is unnecessary noise.

**Fix:** Remove the `typeof window` checks. Since this is in a client component and `Tooltip` only renders when `hover` state is set (user interaction), `window` is guaranteed to be defined.

### L3 — `toCatalogMovie` non-null assertion without guard
**File:** `lib/data.ts:419`

```ts
sum: m.sum!,
```

`toCatalogMovie` is only called on `rated` (filtered to `m.sum != null`), so the assertion is correct — but the connection between the filter and the assertion is not obvious and a future refactor could break it silently.

**Fix:** Add an inline guard or explicit filter comment, or use `m.sum ?? 0` with a comment explaining why null is impossible at this call site.

### L4 — `monthLabel` returns locale-formatted date using server locale
**File:** `lib/data.ts:138–141`

```ts
function monthLabel(raw: string | null | undefined): string {
  const iso = cleanDate(raw);
  if (!iso) return '— older —';
  const d = new Date(iso);
  if (Number.isNaN(d.getTime())) return iso;
  return d.toLocaleString('en-US', { month: 'short', year: 'numeric', timeZone: 'UTC' });
}
```

`monthLabel` is called in `buildTimeline()` which runs **at build time** on Vercel's build servers. Since `'en-US'` is explicitly specified as the locale and `timeZone: 'UTC'` is set, this is deterministic across environments. No issue in practice, but worth noting.

### L5 — Large inline SVG data-URI in CSS
**File:** `app/globals.css:39`

```css
background-image: url("data:image/svg+xml;utf8,<svg xmlns='...'><filter id='n'>...</filter>...</svg>");
```

An inline SVG data URI is used for the grain noise texture overlay on `.stage::after`. This is fine for a small SVG, but the SVG is not URL-encoded (it uses raw UTF-8 with single quotes). Some older browsers may mis-parse the `utf8` encoding declaration or the unencoded characters. Modern browsers handle it correctly.

**Fix (optional):** URL-encode the SVG data URI or convert to a proper base64 data URI to guarantee cross-browser parsing. Low priority.

### L6 — `rank-row` CSS rule declared twice
**File:** `app/globals.css:615–624` and `app/globals.css:661–671`

`.rank-row` is declared twice. The second declaration sets `background: transparent`, `border: none`, etc. and overrides the grid layout from the first. This works due to cascade order but is confusing.

**Fix:** Merge the two `.rank-row` rule blocks into one.
