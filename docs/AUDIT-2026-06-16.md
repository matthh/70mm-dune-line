## HIGH

### H1 — `window.open` with user-controlled URL *(carryover from 2026-06-09)*
**File:** `app/Timeline.tsx:357`

`m.wikiUrl` is a template string over `m.id` from the JSON at runtime. TypeScript
types `m.id` as `number`, but the JSON is consumed via an unchecked cast
(`raw as RawData`). A malicious upstream response could inject a non-numeric id
that becomes a `javascript:` URL.

**Recommended fix (one-liner guard in `Timeline.tsx`):**
```tsx
onClick={() => {
  if (m.wikiUrl.startsWith('https://70mmwiki.com/')) {
    window.open(m.wikiUrl, '_blank', 'noopener,noreferrer');
  }
}}
```
Or sanitize at construction time in `lib/data.ts`:
```ts
wikiUrl: `https://70mmwiki.com/movies/${Math.abs(Math.floor(Number(m.id)))}`,
```

### H2 — No runtime validation of `movies.json` shape *(carryover from 2026-06-09)*
**File:** `lib/data.ts:264`

The entire data pipeline trusts that the committed JSON matches `RawData`.
The JSON is fetched from `70mmwiki.com` by a GitHub Actions bot. If the upstream
API changes its shape (field rename, type change), the site fails silently at
runtime rather than loudly at build time.

**Recommended fix:** Add at minimum a startup assertion before iterating:
```ts
if (!Array.isArray((data as RawData).movies)) {
  throw new Error('movies.json: expected movies array');
}
```
For stronger coverage, introduce Zod or similar for the `RawMovie` shape.

### H3 — PostCSS XSS vulnerability in build toolchain *(new)*
**File:** `package.json` (via `next@16.2.6` → `postcss@8.4.31`)  
**CVE:** GHSA-qx2v-qp2m-jg93

PostCSS versions `< 8.5.10` have an XSS vulnerability in their CSS Stringify
output (unescaped `</style>` tags). This affects **build-time tooling only** —
the deployed static bundle is pre-built HTML/CSS/JS and PostCSS never runs in
production. Risk to end users is therefore zero. Risk to the CI/CD pipeline or
any developer who injects untrusted CSS through the build pipeline is low but
non-zero.

**Recommended fix:** Bump `next` to the latest patch (`^16.2.9` as of 2026-06-16);
Next.js 16.2.9 ships with postcss ≥ 8.5.10. Update `package.json`:
```json
"next": "^16.2.9"
```
then `npm install`. This is a patch-only change; verify the build still passes
(`npm run build`) before committing.

**Do not use `npm audit fix --force`** — that would downgrade Next.js to 9.x,
which is a breaking change.

## MEDIUM

### M1 — `useMemo` suppresses exhaustive-deps lint rule *(carryover)*
**File:** `app/Timeline.tsx:166`

```tsx
}, [bands, sortMode, active]); // eslint-disable-line react-hooks/exhaustive-deps
```

`isVisible` (defined inline, depends on `active` and `sortMode`) is used inside
the `useMemo` but not listed in deps. The eslint suppression hides this. The
current implementation is safe (function is stable w.r.t. `active`/`sortMode`),
but a refactor of `isVisible` could silently introduce a stale-closure bug.

**Recommended fix:** Wrap `isVisible` in `useCallback` so it can be listed as a
dep safely, then remove the eslint-disable comment.

### M2 — Keyboard handler re-registers on every parent render *(carryover)*
**File:** `app/AllTimeStats.tsx:252–262`

`onClose` is passed as `() => setPopup(null)` — a new function reference every
parent render — so the `useEffect` that registers the keydown handler fires every
time the parent re-renders, removing and re-adding the listener unnecessarily.
Functional but wasteful.

**Recommended fix:** Memoize `onClose` with `useCallback` in
`AllTimeStatsSection`, or use `setPage(p => p + 1)` functional updater and drop
`page`/`onClose` from the deps array.

---

### M3 — `at-row.clickable` styles ignored due to `display: contents` *(carryover)*
**File:** `app/globals.css:504–506, 662–664`

`.at-row` is `display: contents`, so it has no layout box. The
`.at-row.clickable` rules (`background`, `padding`, `margin`, `border-radius`,
`cursor`) are all box-model properties that have no effect on a
`display: contents` element. The hover highlight and cursor never render.

Note: `focus-visible` outline added to `.at-row.clickable` in the 2026-06-09
audit does apply to child elements that gain focus — so keyboard accessibility
is partially addressed — but the hover background still does not render.

**Recommended fix:** Wrap each category row in a `<div>` wrapper (not
`display: contents`) and apply grid column spans to it, or change the grid
structure so the row wrapper has a real box. Then the hover/cursor styles will
work.

---

### M4 — GitHub Actions workflow uses broad `contents: write` *(carryover)*
**File:** `.github/workflows/refresh.yml:17–18`

The `contents: write` permission is scoped to the entire job. If the scraper or
any of its transitive npm dependencies were compromised in a supply-chain attack,
the Actions token could push arbitrary commits.

**Recommended fix:** Split into two jobs:
1. `scrape` job — no elevated permissions, runs the scraper, uploads
   `data/movies.json` as an artifact.
2. `commit` job — `permissions: { contents: write }`, downloads the artifact, diffs
   it, commits and pushes only if changed.

## LOW

### L1 — No keyboard affordance on `.bar-col` click targets *(carryover)*
**File:** `app/Timeline.tsx:350–358`

Each chart bar (`<div class="bar-col">`) has an `onClick` that opens the wiki
page but no `role="button"`, `tabIndex`, or `onKeyDown`. Keyboard-only users
cannot navigate to or activate individual bars.

**Recommended fix:**
```tsx
<div
  role="button"
  tabIndex={0}
  onKeyDown={(e) => {
    if (e.key === 'Enter' || e.key === ' ') {
      window.open(m.wikiUrl, '_blank', 'noopener,noreferrer');
    }
  }}
  ...
>
```

### L2 — Non-null assertion `m.sum!` disconnected from its guard *(carryover)*
**File:** `lib/data.ts:419`

```ts
sum: m.sum!,
```

`toCatalogMovie` is only ever called on `rated` (filtered to `m.sum != null`),
but the assertion is separated from the filter site. A future refactor could call
`toCatalogMovie` on an unfiltered list and the assertion would hide the bug
rather than surface it.

**Recommended fix:** Add a comment at the call site, or change to
`m.sum ?? 0 /* never: filtered above */`.

---

### L3 — Large inline SVG grain texture is not URL-encoded *(carryover)*
**File:** `app/globals.css:39`

The SVG data URI uses `utf8` encoding declaration with raw (non-encoded)
characters. This works in all modern browsers but is technically malformed per
spec. Low risk in practice.

**Recommended fix (optional):** URL-encode the SVG or use base64 encoding.

---

### L4 — `MONTH_THEME_OVERRIDES` map growing without pruning *(ongoing)*
**File:** `scripts/scrape.mjs:27–61`

The map now has ~40 entries (added 2 new ones since the 2026-06-09 audit:
entries 438 and 425). The scraper logs `REDUNDANT` warnings when the wiki
catches up, but there is no automated pruning. Stale entries accumulate.

**Recommended fix:** After each scrape run that produces `REDUNDANT` warnings,
remove the flagged entries from the map. Consider adding a CI lint step or
post-scrape script that checks for and removes stale overrides automatically.
