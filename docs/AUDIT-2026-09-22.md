## Medium

### M-1 · GitHub Actions `contents: write` permission too broad — carry-over from 2026-07-21

**File:** `.github/workflows/refresh.yml` (lines 17–18)
**Finding:** `permissions: contents: write` is declared at the workflow level.
The `node scripts/scrape.mjs` step executes untrusted network I/O (70mmwiki.com
and Spotify's oEmbed) while the elevated token is in scope. A supply-chain
compromise of either external endpoint during a scrape run could use the token
to push arbitrary commits.
**Fix:** Scope the `contents: write` permission to only the commit/push step:
```yaml
permissions:
  contents: read   # workflow level — read only
jobs:
  refresh:
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Run scraper
        run: node scripts/scrape.mjs
      - name: Commit if data changed
        permissions:
          contents: write   # scoped to this step only
        run: |
          git config user.name "70mm-dune-line bot"
          ...
```
Not applied — requires workflow restructuring and re-testing in a live Actions
run.

## Low

### L-1 · `.at-row.clickable` hover styles have no effect — carry-over from 2026-06-09

**File:** `app/globals.css` (lines 504–506, 662–664)
**Finding:** `.at-row { display: contents; }` collapses the element out of the
box model, so `background`, `cursor`, `border-radius`, `transition`, and
`padding` rules on `.at-row.clickable` have no rendered effect. The intended
click-affordance hover highlight for leaderboard rows is invisible.
**Fix:** Change `.at-row` to CSS subgrid so it participates in the box model
while keeping the 3-column layout intact:
```css
.at-row {
  display: grid;
  grid-column: 1 / -1;
  grid-template-columns: subgrid;
  align-items: center;
  border-radius: 4px;
}
/* .at-row.clickable hover rules then take effect as written */
```
CSS subgrid is supported in all evergreen browsers (Chrome 117+, Firefox 71+,
Safari 16+). Not applied — requires visual regression check against the
leaderboard layout.

### L-2 · Hardcoded Dune wiki id `91` — accepted known assumption

**File:** `lib/data.ts:277`
**Finding:** `const isDune = m.id === 91`. If the wiki re-keys this entry, the
Dune Line categorisation silently breaks.
**Status:** Accepted. Wiki has never re-keyed a movie; the value has been stable
since the app launched.

### L-3 · `isVisible` defined inside component with suppressed lint warning — carry-over from 2026-07-21

**File:** `app/Timeline.tsx` (line 128, `// eslint-disable-line` on line 166)
**Finding:** `isVisible` is a plain function in the component body, used inside
a `useMemo` whose `react-hooks/exhaustive-deps` warning is suppressed. The
captured variables (`sortMode`, `active`) are correctly listed in the deps
array today; the suppression becomes a stale-closure hazard if the function
closes over additional state and the deps array isn't updated to match.
**Fix:** Wrap `isVisible` in `useCallback` so it can be a legitimate dependency
in the `useMemo` array, then remove the `eslint-disable` comment.

### L-4 · No test suite — carry-over from 2026-07-21

**File:** `lib/data.ts` (all pure functions)
**Finding:** `buildTimeline`, `categoryFor`, `shortenThemeName`, and
`monthLabel` are side-effect-free and deterministic. `movies.json` is large
enough to serve as a realistic fixture. No tests exist.
**Fix:** Add `vitest` as a dev dependency and write unit tests. Estimated
effort: 2–3 hours.

### L-5 · GitHub Actions uses floating major-version tags for actions — carry-over from 2026-08-25

**File:** `.github/workflows/refresh.yml` (lines 24, 28)
**Finding:** `uses: actions/checkout@v4` and `uses: actions/setup-node@v4`
pin to a major-version floating tag rather than a commit SHA. If the upstream
action's `v4` tag is force-pushed with malicious content, the workflow would
execute it with `contents: write` access on the next run. This compounds M-1.
**Fix:** Pin each action to an exact commit SHA, and add a version comment:
```yaml
- uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683  # v4.2.2
- uses: actions/setup-node@39370e3970a6d050c480ffad4ff0ed4d3fdee5af  # v4.1.0
```
Use Dependabot or Renovate to keep these current. Not applied — requires
verifying current tag-to-SHA mappings against the GitHub Actions repo.

### L-6 · `@types/node` version range lags Node LTS — carry-over from 2026-09-08

**File:** `package.json` (line 13)
**Finding:** `"@types/node": "^22.0.0"` resolves to a 22.x version but latest
is 26.x. Low risk as written; flag for next Node LTS bump.
**Status:** Monitor. Acceptable until the project moves to Node 24+.
