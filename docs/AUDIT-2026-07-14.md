## Medium

### M-1 · PostCSS 8.4.31 XSS vulnerability in build toolchain
**File:** `package.json` (via `next@16.2.x`)  
**Finding:** PostCSS ≤ 8.5.9 has a moderate XSS vulnerability (GHSA-qx2v-qp2m-jg93) in its CSS stringify output. PostCSS is a build-time tool — the deployed static bundle is unaffected — but the vulnerability exists in the local dev and CI build environment.  
**Fix:** Update `next` to ≥ 16.2.9, which pulls in `postcss ≥ 8.5.10`. Run `npm update next` and verify the build still produces a clean static export.

### M-2 · GitHub Actions workflow has broad `contents: write` permission
**File:** `.github/workflows/refresh.yml`  
**Finding:** The daily scraper workflow needs write access to commit updated `movies.json`. However, the `contents: write` permission is scoped at the job level (or top level) and applies to the entire workflow, not just the commit step.  
**Fix:** Explicitly scope the permission: set `contents: read` at the top level and override with `contents: write` only on the `git commit/push` step, or scope the token to the minimum via a fine-grained PAT.

## Low

### L-1 · `at-row.clickable` hover styles have no effect
**File:** `app/globals.css`  
**Finding:** `.at-row` uses `display: contents`, so `background`, `cursor`, and box-model properties applied to it are ignored. The "clickable" visual affordance (cursor change, hover highlight) does not render.  
**Fix:** Apply the `cursor: pointer` and hover styles to the child cells (e.g., `td` inside `.at-row`) rather than the row element itself.

### L-2 · Hardcoded Dune wiki id `91`
**File:** `lib/data.ts`  
**Finding:** `isDune = m.id === 91` is a hardcoded constant. If the wiki ever re-keys that movie the Dune Line constant silently breaks.  
**Risk:** Very low — wiki IDs are stable and this is a fan project. Document as a known assumption.

### L-3 · Growing `MONTH_THEME_OVERRIDES` map with no pruning process
**File:** `scripts/scrape.mjs`  
**Finding:** The override map (~35 entries) accumulates stale entries as the wiki catches up. The scraper logs `REDUNDANT` warnings for stale entries but there is no process to act on them.  
**Fix:** After each daily run, review the CI logs for `REDUNDANT` lines and remove the corresponding entries from the map in a follow-up commit. Consider a CI check that fails if any `REDUNDANT` entries are detected.

### L-4 · `isVisible` defined inside a component with suppressed lint warning
**File:** `app/Timeline.tsx`  
**Finding:** `isVisible` is defined inside the `Timeline` component and used inside a `useMemo` with a suppressed `exhaustive-deps` lint warning. The suppression is intentional but fragile if the function signature changes.  
**Fix:** Move `isVisible` outside the component or memoize it with `useCallback` so it can be included in the dependency array legitimately.

### L-5 · No test suite
**Finding:** Zero automated tests. `lib/data.ts` is entirely pure functions (`buildTimeline`, `categoryFor`, `shortenThemeName`) that are straightforward to unit-test.  
**Fix:** Add `vitest` and cover `buildTimeline` with the current `movies.json` snapshot as a fixture. Verify Dune Line categorisation, themeless bucketing, and `isRegular` filtering.
