## Critical

### C-1 · Two new npm vulnerabilities — **FIXED this cycle**

**File:** `package-lock.json`

**Findings:**

1. `GHSA-vcvr-r3jv-pc5j` — **Critical** — Next.js RCE in `next/og`
   ImageResponse API, affects `next` 16.2.0–16.3.5. Fixed in 16.3.8.
2. `GHSA-68fv-2mgg-jv7q` — **High** — `source-map-js` allows event-loop
   denial of service through indexed source-map section offsets, affects
   1.0.0–1.2.1. Fixed in 1.2.2.

**Impact on this app:** The `next/og` RCE affects the ImageResponse API; this
app does not use `next/og` anywhere. `source-map-js` is a build-time
dependency — no server runtime in production. Risk is low in practice, but
pinning vulnerable versions in the lock file is not acceptable even when
mitigated.

**Fix applied:** `npm audit fix` upgraded `package-lock.json` to next@16.3.8
and source-map-js@1.2.2. Build passes. `npm audit` reports zero
vulnerabilities.

## Medium

### M-1 · Scraper User-Agent embeds owner email address (open, pre-existing)

**File:** `scripts/scrape.mjs:16`

```js
const UA = '70mm-dune-line/0.1 (https://github.com/matthh/70mm-dune-line) - fan visualization, contact: matthh@gmail.com';
```

The email address is included intentionally so the wiki maintainers can
reach the scraper operator if it misbehaves — a recognized practice for
polite scraping bots. The address is already public in GitHub commits and the
package.json. No change recommended; noted here for completeness.

## Low

### L-1 · `.at-row.clickable` hover/cursor styles invisible (open, pre-existing)

**File:** `app/globals.css:504–505, 662–664`

```css
.at-row { display: contents; }
.at-row.clickable { cursor: pointer; background: ...; }  /* no visual effect */
```

`display: contents` removes the box, so `background`, `cursor`, and box-model
properties on `.at-row.clickable` have no effect. The click affordance still
works functionally (the event handler fires), but the visual hover indicator
does not render. Open since the 2026-06-09 audit.

**Recommended fix:** Change `.at-row` to `display: grid; grid-column: 1 / -1`
(matching the grid column span of its contents) or restructure the leaderboard
rows so the clickable wrapper is not a `display: contents` element.

### L-2 · No TypeScript strict null check on `toCatalogMovie` `sum` field (open, pre-existing)

**File:** `lib/data.ts:422`

```ts
const toCatalogMovie = (m: RawMovie): CatalogMovie => ({
  ...
  sum: m.sum!,   // non-null assertion
```

`CatalogMovie.sum` is typed as `number` (not `number | null`), but the
assertion bypasses the compile-time check. The call sites (`rated.filter(m =>
m.sum != null)`) do guard it, so this is unlikely to produce a runtime NaN,
but a future refactor could call `toCatalogMovie` on an unrated movie and
silently produce `NaN` sums in the leaderboard. Low risk at current call-site
discipline.

**Recommended fix:** Type `CatalogMovie.sum` as `number | null` to eliminate
the assertion, or add a runtime guard inside `toCatalogMovie` (throw or return
early if `m.sum == null`).

### L-3 · `shortenThemeName` SHORT_NAMES map has a typo key (open, pre-existing)

**File:** `lib/data.ts:162`

```ts
'Holy/Regligion/Spiritual Month': 'Holy Month',
```

The key `'Holy/Regligion/Spiritual Month'` contains `Regligion` (should be
`Religion`). If the wiki fixes the typo in the source data, this override
silently stops firing and the full mis-spelled name renders. The map uses the
wiki string verbatim as the key, which is the correct approach; the typo just
needs to be tracked.

**Recommended fix:** Add a comment noting the typo is intentional (wiki
source data) so future editors don't "correct" it and break the match.

### L-4 · `backfill-csv.mjs` dev utility has no associated documentation (open)

**File:** `scripts/backfill-csv.mjs`

The script is not wired into any CI flow, is gitignored for its output, and
has no mention in `package.json` scripts. Its existence and purpose are
undocumented outside a single ARCHITECTURE.md bullet. Risk of accidental
removal or misuse is low but non-zero for any future contributor unfamiliar
with the repo.

**Recommended fix:** Add a one-line comment header to `backfill-csv.mjs`
describing what it does and when to use it (already noted in ARCHITECTURE.md;
a matching comment in the script itself would make it self-documenting).

### L-5 · No tests (open, pre-existing)

**File:** `lib/data.ts` — pure transformation functions with no test coverage.

`buildTimeline()`, `shortenThemeName()`, `categoryFor()`, and `isRegular()`
are all pure functions with deterministic outputs. A small test suite would
catch regressions in band grouping, category assignment, theme-ranking
eligibility thresholds, and the `toCatalogMovie` null-safety concern above.

**Recommended fix:** Add `vitest` (or `jest`) and a `lib/data.test.ts` with
unit tests for at least `categoryFor()`, `isRegular()`, `shortenThemeName()`,
and the per-category movie list sorting in `buildTimeline()`.
