## Medium

### M-1 · PostCSS 8.4.31 XSS vulnerability in build toolchain — carry-over from 2026-07-21
**File:** `package.json` (via `next@^16.2.4` → resolved `16.2.6`)
**Status:** **Not fixed.** `package-lock.json` still locks to Next.js 16.2.6, which
pulls PostCSS 8.4.31 (CVE GHSA-qx2v-qp2m-jg93, moderate). PostCSS is a
build-time tool only — the deployed static bundle is unaffected — but the
vulnerability exists in the local dev and CI environments.
**Fix:** Update the `next` lower bound to `^16.2.9` in `package.json`, then run
`npm install`. Verify `npm run build` still produces a clean static export.
Do **not** use `npm audit fix --force` — that downgrades Next.js to 9.x.

### M-2 · GitHub Actions `contents: write` permission too broad — carry-over from 2026-07-21
**File:** `.github/workflows/refresh.yml`
**Status:** **Not fixed.** `permissions: contents: write` is scoped at the job
level and applies to the entire workflow — including the `node scripts/scrape.mjs`
step that runs untrusted network I/O.
**Fix:** Set `contents: read` at the top-level `permissions` block; override with
`contents: write` only for the commit/push step, or split into two jobs (scrape
with no elevated permissions, then commit with `contents: write`).

## Low

### L-1 · `.at-row.clickable` hover and cursor styles have no effect — carry-over from 2026-07-21
**File:** `app/globals.css` (line 504 and 662)
**Status:** **Not fixed.** `.at-row` uses `display: contents`, which means the
element itself has no layout box. All box-model properties applied to
`.at-row.clickable` — `background`, `cursor`, `border-radius`, `padding`,
`margin` — are ignored by the browser. The hover highlight and cursor affordance
never render.
**Fix:** Either (a) wrap each category row in a real `<div>` that spans all three
grid columns and apply the styles there, or (b) apply `cursor: pointer` and the
hover background to the direct children (`.at-label`, `.at-bar`, `.at-count`)
under `.at-row.clickable` instead of the row element itself.

### L-2 · Hardcoded Dune wiki id `91` — accepted known assumption
**File:** `lib/data.ts` (line 272)
**Status:** Accepted. Wiki IDs are stable; this is a fan project. No action unless
the wiki re-keys the entry.

### L-3 · Growing `MONTH_THEME_OVERRIDES` map with no pruning process — carry-over from 2026-07-21
**File:** `scripts/scrape.mjs` (lines 26–61)
**Status:** **Not fixed.** The map currently holds 34 entries. The scraper logs
`REDUNDANT` warnings as the wiki catches up, but no one reviews or acts on them.
**Fix:** Review CI logs after each daily run for `REDUNDANT` lines and prune the
flagged entries. Consider a CI check that exits non-zero if any `REDUNDANT` log
line is emitted.

### L-4 · `isVisible` defined inside component with suppressed lint warning — carry-over from 2026-07-21
**File:** `app/Timeline.tsx` (line 128, suppression on line 166)
**Status:** **Not fixed.** `isVisible` is defined inside `Timeline` and used
inside a `useMemo` whose dependency array suppresses `exhaustive-deps`. Correct
today (function is stable relative to `active`/`sortMode`), but fragile.
**Fix:** Move `isVisible` outside the component or memoize it with `useCallback`
so it can appear in the dependency array legitimately and the eslint-disable
comment can be removed.

### L-5 · No test suite — carry-over from 2026-07-21
**Status:** **Not fixed.** `lib/data.ts` is entirely pure functions
(`buildTimeline`, `categoryFor`, `shortenThemeName`) that are straightforward to
unit-test. Zero automated tests exist.
**Fix:** Add `vitest` and cover `buildTimeline` with the current `movies.json` as
a fixture. Verify Dune Line categorisation, themeless bucketing, `isRegular`
filtering, and `shortenThemeName` word-boundary truncation.

### L-6 · `backfill.csv` tracked in git despite `.gitignore` entry — **FIXED this cycle**
**File:** `backfill.csv` (repo root)
**Status:** **Fixed.** The 2026-06-09 audit added `backfill.csv` to `.gitignore`
but did not run `git rm --cached backfill.csv`. The file remained tracked in the
git index through every subsequent audit until this one. `git rm --cached
backfill.csv` was run this cycle; the file is now correctly untracked. It remains
on disk (gitignored) for local use via `node scripts/backfill-csv.mjs`.
