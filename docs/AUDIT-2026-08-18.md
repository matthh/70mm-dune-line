## Medium

### M-1 · GitHub Actions `contents: write` permission too broad — carry-over from 2026-07-21

**File:** `.github/workflows/refresh.yml` (lines 17–18)
**Finding:** `permissions: contents: write` is declared at the workflow level.
The `node scripts/scrape.mjs` step executes untrusted network I/O (70mmwiki.com
and Spotify's oEmbed) while the elevated token is in scope. A supply-chain
compromise of either external endpoint during a scrape run could use the token
to push arbitrary commits.
**Fix:** Set `permissions: contents: read` at the workflow level and override
with `contents: write` only in the specific step that does the `git push` —
or split into two jobs (scrape → commit) where only the commit job has write
permission.

## Low

### L-1 · `.at-row.clickable` hover styles have no effect — carry-over from 2026-06-09

**File:** `app/globals.css` (lines 504–506, 662–664)
**Finding:** `.at-row { display: contents; }` collapses the element out of the
box model, so `background`, `cursor`, `border-radius`, and `transition` rules
on `.at-row.clickable` have no rendered effect. The intended click-affordance
hover highlight for leaderboard rows is invisible to users.
**Fix:** Change `.at-row` to use CSS subgrid so it participates in the box
model while keeping the 3-column layout intact:
```css
/* .all-time-grid stays as-is */
.at-row {
  display: grid;
  grid-column: 1 / -1;
  grid-template-columns: subgrid;
  align-items: center;
  border-radius: 4px;
}
/* .at-row.clickable hover rules then take effect as written */
```
CSS subgrid is supported in all evergreen browsers (Chrome 117+, Firefox 71+,
Safari 16+). Not applied this cycle — requires visual regression check.

### L-2 · Hardcoded Dune wiki id `91` — accepted known assumption

**File:** `lib/data.ts:272`
**Finding:** `const isDune = m.id === 91`. If the wiki re-keys this entry, the
Dune Line categorisation silently breaks.
**Status:** Accepted. Wiki has never re-keyed a movie; the value is stable.

### L-3 · `MONTH_THEME_OVERRIDES` map accumulates stale entries — carry-over from 2026-07-21

**File:** `scripts/scrape.mjs` (lines 27–61, 34 entries)
**Finding:** Manual theme-correction entries are never pruned automatically.
The scraper logs `override REDUNDANT` warnings when the wiki catches up, but
these warnings aren't surfaced in CI (no failure, no alert).
**Fix:** Periodically run `node scripts/scrape.mjs` locally and grep for
`REDUNDANT` to identify entries safe to delete. A future improvement would
add a CI step that fails on any REDUNDANT warning.

### L-4 · `isVisible` defined inside component with suppressed lint warning — carry-over from 2026-07-21

**File:** `app/Timeline.tsx` (line 128, `// eslint-disable-line` on line 166)
**Finding:** `isVisible` is a plain function inside the component body, used
inside a `useMemo` whose `react-hooks/exhaustive-deps` warning is suppressed.
Correct today but fragile — if `isVisible` ever closes over additional state,
the suppression masks a stale-closure bug.
**Fix:** Wrap `isVisible` in `useCallback` so it can appear as a legitimate
dependency in the `useMemo` array, then remove the `eslint-disable` comment.

### L-5 · No test suite — carry-over from 2026-07-21

**File:** `lib/data.ts` (all pure functions)
**Finding:** `buildTimeline`, `categoryFor`, `shortenThemeName`, and
`monthLabel` are side-effect-free and deterministic. They have no tests.
**Fix:** Add `vitest` as a dev dependency and write unit tests using
`data/movies.json` as the fixture. Estimated effort: 2–3 hours.
