## Medium

### M-1 · PostCSS 8.4.31 XSS vulnerability in build toolchain — carry-over from 2026-07-21
**File:** `package.json` (via `next@^16.2.4` → resolved `16.2.6`)
**Status:** **Not fixed.** `package-lock.json` still locks to Next.js 16.2.6,
which pulls PostCSS 8.4.31 (CVE GHSA-qx2v-qp2m-jg93, moderate). PostCSS is a
build-time tool only — the deployed static bundle is unaffected — but the
vulnerability exists in the local dev and CI environments.
**Fix:** Update the `next` lower bound to `^16.2.9` in `package.json`, then run
`npm install`. Verify `npm run build` still produces a clean static export.
Do **not** use `npm audit fix --force` — that downgrades Next.js to 9.x.

### M-2 · GitHub Actions `contents: write` permission too broad — carry-over from 2026-07-21
**File:** `.github/workflows/refresh.yml`
**Status:** **Not fixed.** `permissions: contents: write` is scoped at the job
level and applies to the entire workflow — including the `node scripts/scrape.mjs`
step that runs untrusted network I/O against 70mmwiki.com and the Spotify oEmbed
endpoint. A compromised wiki response or a future supply-chain issue could
leverage this elevated token.
**Fix:** Set `contents: read` at the top-level `permissions` block; override with
`contents: write` only for the commit/push step, or split into two jobs (scrape
with no elevated permissions, then commit with `contents: write`).

## Low

### L-1 · `.at-row.clickable` hover and cursor styles have no effect — carry-over from 2026-07-21
**File:** `app/globals.css` (lines 504–505, 662–664)
**Status:** **Not fixed.** `.at-row` uses `display: contents` (line 505), which
means the element itself has no layout box. All box-model properties on
`.at-row.clickable` — `cursor: pointer`, `background`, `border-radius`,
`padding`, `margin`, hover and focus-visible states — are ignored by the browser.
The pointer cursor and hover highlight affordance never render.
**Fix:** Apply `cursor: pointer` and the hover background to the direct children
(`.at-label`, `.at-bar`, `.at-count`) under `.at-row.clickable` rather than the
grid-row element itself. Or introduce a real wrapper `<div>` spanning all three
columns.

### L-2 · Hardcoded Dune wiki id `91` — accepted known assumption
**File:** `lib/data.ts` (line 272)
**Status:** Accepted. Wiki IDs are stable; this is a fan project. No action
unless the wiki re-keys the entry.

### L-3 · Growing `MONTH_THEME_OVERRIDES` map with no automated pruning — carry-over from 2026-07-21
**File:** `scripts/scrape.mjs` (lines 26–61, 34 entries)
**Status:** **Not fixed.** The scraper logs `REDUNDANT` warnings as the wiki
catches up, but no one systematically reviews or acts on them. Count holds
at 34 entries.
**Fix:** Review CI logs after each daily run for `REDUNDANT` lines and prune the
flagged entries. A lightweight approach: add a CI step that tails the scrape
output and `grep -q "REDUNDANT"` to emit a warning annotation when stale entries
are found.

### L-4 · `isVisible` defined inside component with suppressed lint warning — carry-over from 2026-07-21
**File:** `app/Timeline.tsx` (line 128, suppression on line 166)
**Status:** **Not fixed.** `isVisible` is defined inside `Timeline` and called
inside a `useMemo` whose dependency array suppresses `react-hooks/exhaustive-deps`
(eslint-disable-line comment on line 166). The suppression is correct today
(function is stable relative to `active`/`sortMode`), but fragile if the
function signature changes.
**Fix:** Memoize `isVisible` with `useCallback` so it can appear in the
dependency array legitimately and the eslint-disable comment can be removed.

### L-5 · No test suite — carry-over from 2026-07-21
**Status:** **Not fixed.** `lib/data.ts` is entirely pure functions
(`buildTimeline`, `categoryFor`, `shortenThemeName`) that are straightforward to
unit-test. Zero automated tests exist.
**Fix:** Add `vitest` and cover `buildTimeline` with the current `movies.json`
as a fixture. Verify Dune Line categorisation, themeless bucketing, `isRegular`
filtering, and `shortenThemeName` word-boundary truncation.

### L-7 · `RATING_OVERRIDES` entry 441 (Lincoln) was redundant — **FIXED this cycle**
**File:** `scripts/scrape.mjs` (previously line 71)
**Status:** **Fixed.** The wiki now publishes `sum=10` for Lincoln (movie id
441), making the manual override value (`10.5`) permanently dead code. The
scraper would have logged "override REDUNDANT" on every run since the wiki
published the rating. Removed from `RATING_OVERRIDES` this cycle; the map is
now empty. The placeholder comment is retained so the pattern is discoverable
when new overrides are needed.
