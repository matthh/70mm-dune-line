## Security

### C-1 · Three npm vulnerabilities in `package-lock.json` — **FIXED this cycle**

**File:** `package-lock.json`

**Findings:**

1. **Critical** — `next 16.0.0 – 16.3.7`: Multiple CVEs including RCE in
   `next/og` ImageResponse (`GHSA-vcvr-r3jv-pc5j`), cache poisoning in SSG/ISR
   (`GHSA-mcj8-r9mp-w47p`, `GHSA-4jqv-mc3x-m676`), pending `use cache` Draft
   Mode leak (`GHSA-3w37-wq28-93x7`), information disclosure in development
   server MCP endpoint (`GHSA-39w2-rjm5-chcv`), SSRF in Image Optimization
   (`GHSA-cjq9-62q9-8jv4`), and metadata image route dynamicParams bypass
   (`GHSA-f87g-xv8r-7p7x`). Fixed in 16.4.0.

2. **High** — `source-map-js 1.0.0 – 1.2.1`: Event-loop denial of service via
   indexed source-map section offsets (`GHSA-68fv-2mgg-jv7q`). Fixed in 1.2.2.

3. **High** — `sharp < 0.35.5`: Vulnerability in `librsvg` dependency
   (`GHSA-wq5f-xc86-pv6w`, CVE-2026-96889). Fixed in 0.35.5. `sharp` is an
   optional transitive dependency pulled in by Next.js for image optimization;
   this site does not use `next/image` or `next/og`, so runtime exposure is nil,
   but the lock file should not reference a vulnerable version.

**Impact on this app:** The `next/og` RCE and SSRF affect APIs not present in
this static-export site; the cache-poisoning CVEs require a server runtime
(none exists here); the development-server information disclosure only applies
during `npm run dev`. `sharp/librsvg` is a build-time optional dependency.
Risk is low in practice, but pinning vulnerable lock-file entries is not
acceptable regardless of deployment model.

**Fix applied:** `npm audit fix` upgraded `package-lock.json` to
next@16.4.0, source-map-js@1.2.2, sharp@0.35.5. Build passes. `npm audit`
reports zero vulnerabilities.

## Performance

### P-1 · `movies.json` bundle size continues to grow (open, pre-existing)

**File:** `data/movies.json`

The dataset is statically imported at build time and bundled into the client
JavaScript. At 465 total entries (~200 KB) it remains within comfortable bounds.
Growth rate is roughly 3–4 new regular episodes per month. At the current
rate (~40 KB per year) this remains low priority for at least 2–3 years before
bundle size becomes a concern.

**Recommended fix (future):** If the dataset grows past ~600 KB, consider
switching from a static import to a `fetch` in a Server Component or splitting
the JSON into per-band chunks. No action needed now.

## Maintainability

### M-1 · Scraper User-Agent embeds owner email address (open, pre-existing)

**File:** `scripts/scrape.mjs:16`

```js
const UA = '70mm-dune-line/0.1 (https://github.com/matthh/70mm-dune-line) - fan visualization, contact: matthh@gmail.com';
```

The email address is included intentionally so the wiki maintainers can
reach the scraper operator if it misbehaves — a recognized practice for
polite scraping bots. The address is already public in GitHub commits and the
package.json. No change recommended; noted here for completeness.

### L-1 · `.at-row.clickable` hover/cursor styles invisible (open, pre-existing)

**File:** `app/globals.css` (approximately line 504–505, 662–664)

```css
.at-row { display: contents; }
.at-row.clickable { cursor: pointer; background: ...; }  /* no visual effect */
```

`display: contents` removes the box, so `background`, `cursor`, and box-model
properties on `.at-row.clickable` have no effect. The click affordance still
works functionally (the event handler fires), but the visual hover indicator
does not render. Open since the 2026-06-09 audit.

**Recommended fix:** Change `.at-row` to `display: grid; grid-column: 1 / -1`
(matching the grid column span of its contents) or restructure the leaderboard
rows so the clickable wrapper is not a `display: contents` element.

---

### L-2 · Non-null assertion on `toCatalogMovie` `sum` field (open, pre-existing)

**File:** `lib/data.ts:422`

```ts
sum: m.sum!,   // non-null assertion
```

`CatalogMovie.sum` is typed as `number` (not `number | null`), but the
assertion bypasses the compile-time check. Call sites filter for `m.sum != null`
before calling `toCatalogMovie`, so no runtime NaN is produced today, but a
future refactor could call it on an unrated movie and silently produce NaN
leaderboard sums.

**Recommended fix:** Type `CatalogMovie.sum` as `number | null` and remove the
assertion, or add a runtime guard inside `toCatalogMovie`.

### L-3 · `shortenThemeName` SHORT_NAMES key contains a typo (open, pre-existing)

**File:** `lib/data.ts:162`

```ts
'Holy/Regligion/Spiritual Month': 'Holy Month',
```

The key `'Holy/Regligion/Spiritual Month'` contains `Regligion` (should be
`Religion`). This is intentional: the key mirrors the wiki source data verbatim.
If the wiki fixes the typo the override silently stops firing.

**Recommended fix:** Add an inline comment noting the typo is from the wiki
source so future editors don't "fix" it and break the match.

### L-5 · No tests (open, pre-existing)

**File:** `lib/data.ts` — pure transformation functions with no test coverage.

`buildTimeline()`, `shortenThemeName()`, `categoryFor()`, and `isRegular()`
are all pure functions with deterministic outputs. A small test suite would
catch regressions in band grouping, category assignment, theme-ranking
eligibility thresholds, and the `toCatalogMovie` null-safety concern above.

**Recommended fix:** Add `vitest` (or `jest`) and a `lib/data.test.ts` with
unit tests for at least `categoryFor()`, `isRegular()`, `shortenThemeName()`,
and per-category movie list sorting in `buildTimeline()`.
